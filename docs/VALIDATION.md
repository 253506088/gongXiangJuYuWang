## 1.2.1 平板大文件卡住修复

此前 Windows 收齐浏览器上传后，向另一台主机发整文件长 POST；发送进度只计浏览器上传，接收端要到整文件结束才出现，长连接中断会造成“等待对方接收”且无法续传。现主机之间复用 4 MB 分块与远端持久任务，健康连接 8 秒检查、分块 90 秒超时，有限重试，ACK 丢失通过远端偏移恢复；发送缓存保留供续发。

状态包含 deliveredBytes、phase 和目标地址。后台已缓冲任务可直接继续发送，不用重选文件；支持暂停，重启后通过保存的远端任务和内部会话恢复断点。Android 创建传输时即通知，每个分块更新收件进度，完整文件先进入收件箱，系统下载副本后台复制并显示保存状态，避免整文件二次复制阻塞回执。

40 项 Node 测试通过，新增丢回执恢复、超时重试、暂停与跨重启新管理员续传、一次记账、超过 2 GiB 的真实稀疏文件偏移。Android 64 MB 中断续传及超 2 GiB 偏移专项通过，见 android/VALIDATION.md。实际用户平板 http://192.168.0.11:53317、serverId 043ceed9-50ea-4ef6-9a82-c64d52524b4c、旧 1.2.0 服务通过新 Windows 分块发送 16,778,129 字节，匿名下载 SHA-256 一致（e76d05cba66b875fa0827951707cffc324d483f83ef2c7492dbe8017f02418b8），测试文件出现在平板真实收件箱。随后从用户电脑保留缓存续发实际 2.24 GiB 视频；两端偏移均在实时增长。
实际视频完成：2,403,899,808 字节的 S2-01 视频在真实平板系统下载/邻波落盘，主机任务 status=complete、deliveredBytes=size。匿名 HEAD 长度准确，HTTP Range 分别核对 offset=0、1,201,949,904、2,403,834,272 的各65,536字节，全部与电脑 F 盘原文件一致。此大文件验证是完整长度加三个位置字节对照，并未声称整部SHA-256。截图 tablet-real-completed.jpg。
